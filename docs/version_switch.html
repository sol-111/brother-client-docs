テンプレDL版から画像生成版への
切り替え設計

9月14日にテンプレートダウンロード版、10月5日に画像生成版をユーザーへ提供します。この切り替えを、当日の作業なしで自動的に成立させる方式をまとめました。動線の表示条件と、ページの入口をふさぐ条件に切替日時を仕込みます。その日時はDBの値で持ちます。

01

結論

2本の動線に表示条件を付ける。当日の作業はない

サイドメニューの動線を2本に分け、それぞれに表示条件を付けます。現在日時が切替日時を跨いだ時点で、動線は自動的に入れ替わります。10月5日に人が行う作業はありません。

動線表示する条件条件の意味
デザインテンプレ遷移先: design_tempCurrent User's Created Date < 切替日時登録が切替日時より前のユーザーにだけ表示する。切替後も既存ユーザーには残る
行事一覧遷移先: designCurrent date/time >= 切替日時切替日時を過ぎたら全ユーザーへ表示する
開発者向け: 条件を書くときに必要な情報
登録日として使う項目

User に登録日のカスタム項目はありません。組み込みの Created Date を使います。privacy rule に self（view_all: true）があるため、Current User's Created Date は本人から読めます。

条件を付ける対象

Side_main_menu の「行事一覧」（page_name = design）と「デザインテンプレ」（page_name = design_temp）の2値です。ここに日時条件を置きます。

決定: 9月14日の提供に向けて作った仕組みに条件を足すだけで、10月5日の切り替えは自動になります。
  • 2つの条件は、必ず同じ切替日時を参照してください。別々の値を書くと、片方だけ直したときに動線が1本も出ない時間帯が生まれます。
  • 動線を隠してもURLは生きています。ページの入口をふさぐ条件も別に必要です（2章）。切替日時は式に直接書かず、DBの値として持ちます（3章）。
  • この資料は書き出しファイル brother-86284.bubble を読んで作成しました。設計は9月8日 13時30分の書き出しにもとづきます。5章のレビューは9月10日 13時22分の書き出しです。
02

ページの入口をふさぐ

動線を隠しても、URLは生きている
リスク: サイドメニューの動線を隠しても、/design を直接開けば画像生成版に入れます。ブックマークや履歴からの再訪でも同じです。

design ページのリダイレクトは、もともと条件なしで常に動く作りでした。オプションセットの説明欄にある切り替え手順も「これを削除する」前提で書かれています。削除ではなく、1章と同じ条件を付ける形に置き換えます。

対象入れる条件入れないと起きること
design の Page Load のリダイレクトCurrent date/time < 切替日時 のときだけ動かす切替後もテンプレDL版へ飛ばされ続ける
生成の完了・失敗を見張る2つの処理design の「Do when condition is true」2件。生成モニターを更新するCurrent date/time >= 切替日時 のときだけ動かす上のリダイレクトとは逆向き。1章の行事一覧と同じ条件リダイレクトが走る前に評価され、生成モニターのレコードが書き換わる
design_temp 側Current User's Created Date > 切替日時 なら design へ飛ばす切替後に登録したユーザーが、使えない画面に入る
  • この2つは画面を開いている間ずっと条件を見張る処理です。リダイレクトより先に評価される余地があります。画面は一瞬描画されるため、入口をふさぐ手段をリダイレクト1つに頼らないでください。
開発者向け: 条件を足す対象
条件を足す2つの処理の中身

どちらも design ページの「Do when condition is true」（run_when = every_time）で、design_generation_monitor のリスト（要素 bTScm0）を見張っています。

  • 生成の完了（bTSdn0） — 1件以上あるモニターの全件が COMPLETED になったときに走る。ローディングを隠す → 「デザイン生成が完了しました」を表示 → ChangeListOfThings でモニターの deleted_at に現在日時を入れる → custom state を初期化する。
  • 生成の失敗（bTSdX0） — モニターに FAILED が1件以上あるときに走る。ローディングを隠す → 「生成に失敗したサイズがあります」を表示 → 同じく deleted_at を入れる → custom state を初期化する。

この2つには Current date/time >= 切替日時 を足してください。リダイレクトの条件は <、こちらは >= で向きが逆になります。切替後だけ動く処理にするためです。custom state を初期化しているだけの ConditionTrue も同じ条件で揃えておくと安全です。

いま入口をふさいでいる場所

design ページ（bTKwz）の PageLoaded に ChangePage が1アクションだけ入っています。遷移先は design_temp（bTTvd）です。9月10日の書き出しでは、ここに Current Date/Time < 切替日時 の条件が付いています。

外部から直接呼べる経路

画像生成系の Backend Workflow（trigger_generated_image / generated_image / parent_re_generated_image など）は expose = false です。ページの入口をふさげば、生成を外から起動する経路は残りません。expose = true かつ認証不要は email_duplication_check と change_email の2本で、本件とは別に確認が必要です。

置き換える手順

オプションセットの説明欄にある「Roleにエンドユーザーを追加」「テンプレート版のRoleを解除」「design の page load のリダイレクトを削除」の3手順は、今回の条件付きの入口制御に置き換わります。説明欄も更新してください。

03

切替日時の持ち方

式に直接書かず、DBの値で持つ

切替日時は「2026年10月5日 9時00分」です。これを式に直接書くか、DBの値として持つかで、あとから効いてくる差が3つあります。DBの値で持ってください。

理由 1

延期にデプロイが不要になる

8月20日の議事録のとおり、画像生成はテキスト置換が期待どおりに動かず、ユーザー提供の水準に達していません。10月5日に品質が揃うかは未確定です。式に日時を直接書くと、揃っていなくても9時00分に自動で切り替わります。止めるには式を書き換えてデプロイする作業が発生します。DBの値なら日時を先送りするだけで済みます。

理由 2

切り戻しも同じ操作でできる

切り替えたあとに問題が出た場合も、日時を先送りすれば動線はテンプレDL版に戻ります。design_temp のページとデザインテンプレの動線を残しておけば、これだけで戻せます。

理由 3

参照が4か所以上に散らない

動線の条件が2本、ページの入口をふさぐ条件を加えると参照箇所は4か所以上になります。日時を各所に直接書くと、片方だけ直したときに動線が1本も出ない時間帯が生まれます。1つの値を全員が参照する形にすれば、その穴は起きません。

補足: オプションセットはアプリの定義側にあるため、値を変えて本番に効かせるにはデプロイが必要です。切替日時はオプションセットではなくDBのレコードで持ってください。

要対応 1

bubble_pages が旧ページ名のままで、design_temp の画面が出ない

各ページは、URLのパスセグメントと bubble_pages の表示名の一致で、自分のページ定義を引いています。引いた定義は共通部品 global の引数として渡され、ログイン要否・メール確認要否・権限の判定に使われます。

bubble_pages の値は design_ver_tempdl のままです。ページ名は design_temp に変わったため、突き合わせが一致しません。定義が空のまま global に渡ります。

効かなくなるもの起きること
画面の表示制御global の is_display_visible が true にならない。本文のグループ「Group Event And Desgin」は、この値が true のときだけ表示される。画面が空のまま出る
未ログイン時のリダイレクトpublic_ is true の分岐が成立せず、ログイン画面へ飛ばない
メール確認のガードneed_mail_confirmation の分岐が成立せず、確認前でも素通りする
権限による振り分けrole_branch_action が走らない

対応は bubble_pages の該当値の表示名と db_value を design_temp に直すことです。ページ名を design_ver_tempdl に戻す選択もあります。どちらにしても、9月14日の提供前に実機で画面が出ることを確認してください。

要対応 2

切替日時が空のときの逃げ道がない

条件がすべて Current User's switch_date を経由します。この項目を埋めているのは共通部品 global の「User is logged in」1か所だけで、走る条件は「role = エンドユーザー かつ switch_date が空」です。

まだ紐付いていないユーザーでは、サイドバーのデザインテンプレも行事一覧も条件が成立しません。動線が1本も出ない状態になります。design の Page Load も同じ理由で「Current Date/Time < 空」が成立せず、リダイレクトが走りません。

サイドバーには is empty の逃げ道が1つもありません（実測0件）。条件を Search for switch_date:first item's date の直接参照へ変えるか、空のときの分岐を足してください。少なくとも Page Load のリダイレクトは「空なら飛ばす」に変えてください。フェイルセーフ側へ倒します。

直接参照へ変えるほうを推奨します。User を経由しなくなるため、次の2つも同時に解消します。ログイン毎のDB書き込みも不要になります。

  • 「User is logged in」がすでにログイン済みのセッションで発火しない場合、既存ユーザーは次のログインまで動線が消える
  • 紐付け処理は role = エンドユーザー のみのため、管理者は switch_date が空のままになる

User 経由の作りを残す場合は、この2点を実機で確認してください。

要対応 3

生成の完了・失敗を見張る2つの処理に条件が入っていない

bTSdX0（失敗の検知）と bTSdn0（完了の検知）の条件に switch_date が含まれていません。2章の表の2行目が未対応です。切替前に /design を直接開かれた場合、リダイレクトより先に評価されて生成モニターの deleted_at が書き換わる余地が残ります。足す条件は Current date/time >= 切替日時 です。リダイレクト側とは向きが逆になる点に注意してください。

リスク: design_temp にも同じ作りの処理が2件あります（ワークフローIDまで同じ）。こちらは切替前に動く必要があるため、条件を足すとテンプレDL版のダウンロード完了の通知が出なくなります。対象は design ページ側だけです。
